# 幽匿共生体设计

## 目标

将现有 `trail_sight` Curios 饰品改造成“幽匿共生体”。保留注册 ID 以兼容已有存档，仅修改显示名称、客户端表现和游戏机制。

佩戴后，玩家获得原版失明和黑暗效果；服务端使用 Minecraft 1.20.1 原版 `VibrationSystem` 监听附近震动，并把震动位置同步给佩戴者。发出震动的生物会积累暴露值，暴露值达到上限后，玩家向该生物发射一次原版监守者音爆。

## 机制规则

### 感知限制

- 饰品激活时由服务端持续刷新原版 `MobEffects.BLINDNESS` 和 `MobEffects.DARKNESS`。
- 两个效果使用短时刷新，摘下饰品后自然过期，不强制移除玩家可能来自其他来源的同类效果。
- 不修改客户端实体渲染器、阴影或 F3 碰撞箱开关；实体仍可正常渲染和显示碰撞箱。
- 不改变服务端实体状态，不影响碰撞、AI、攻击判定和实体同步。

### 震动监听

每个佩戴者对应一个服务端传感器对象：

- 实现 `VibrationSystem` 和 `VibrationSystem.User`；
- 使用 `DynamicGameEventListener<VibrationSystem.Listener>` 注册到当前 `ServerLevel`；
- 使用 `VibrationSystem.Ticker.tick` 复用原版震动的监听半径、遮挡判断、事件选择和传播延迟；
- 监听原版 `GameEventTags.VIBRATIONS`，因此脚步、交互、投掷、落地、破坏、死亡等原版震动都可被接收；
- 穿戴者自身产生的事件不增加自身暴露值；没有来源实体的方块震动只用于显示位置，不产生实体暴露值；
- 传感器只存在于佩戴期间，最多维护有限数量的目标状态，实体离开范围、死亡或超时后清理。

震动回调在原版传播到传感器的位置触发。服务端按玩家收集当前 tick 的震动位置，合并为一个批次数据包发送给对应客户端，并限制单 tick 的最大标记数量，避免高频红石或大量实体造成网络和渲染压力。

### 暴露值与音爆

- 暴露值按“观察玩家 + 发声生物 UUID”独立维护。
- 每次有效震动按配置增加暴露值，默认每次增加 10 点，默认满值为 100。
- 达到满值时只对产生该震动的 `LivingEntity` 触发音爆；触发后该目标暴露值归零，并进入默认 40 tick 冷却。
- 目标失效或离开监听范围后清理状态。
- 音爆复用原版表现：`ParticleTypes.SONIC_BOOM`、`SoundEvents.WARDEN_SONIC_BOOM`、`damageSources().sonicBoom(player)`、10 点伤害以及监守者同款击退和作用范围。

### 客户端震动表现

客户端维护有界的震动标记队列，每个标记包含位置、频率、接收 tick 和可选来源 UUID：

- 在 `AFTER_ENTITIES` 阶段绘制幽匿蓝色震动波纹；
- 默认显示 20 tick，并随年龄淡出；
- 只绘制当前维度、视距内且队列未过期的标记；
- 由服务端批次包驱动，不再客户端扫描所有实体猜测震动。

## 配置

新增或调整客户端/服务端配置：

| 配置项 | 默认值 | 作用 |
| --- | ---: | --- |
| `sculkSymbioteVibrationRadius` | 16 | 震动监听半径，单位格 |
| `sculkSymbioteExposurePerEvent` | 10 | 每次有效震动增加的暴露值 |
| `sculkSymbioteExposureMax` | 100 | 暴露值满值 |
| `sculkSymbioteSonicBoomCooldown` | 40 | 同一佩戴者触发音爆后的冷却 tick |
| `sculkSymbioteMarkerLifetime` | 20 | 客户端震动标记显示时间 |
| `sculkSymbioteMaxMarkersPerTick` | 32 | 单 tick 最多接收/渲染的震动标记数 |
| `sculkSymbioteMaxTrackedSources` | 128 | 单个佩戴者最多维护的暴露目标数 |

服务端配置控制游戏机制，客户端配置只控制显示细节；服务端不加载客户端渲染类。

## 性能与生命周期

- 震动监听由原版事件索引完成，不在每个服务端 tick 扫描全世界实体。
- 失明和黑暗仅在佩戴者的服务端玩家 tick 中按需刷新，不增加全世界扫描。
- 每个玩家只创建一个传感器；卸下饰品立即注销动态监听器并清空状态。
- 暴露目标和客户端震动标记均有数量上限与过期清理。
- 网络包按玩家、按 tick 批量发送，只发送佩戴者监听范围内的震动。
- 所有客户端类放在 `client` 包中，服务端路径不引用 `net.minecraft.client`。
